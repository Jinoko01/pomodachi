# 슬래시 커맨드와 인터랙션

## 커맨드 정의

- 커맨드는 `SlashCommandBuilder`로 정의한다. 새 기능은 기존 `/뽀모도로` 커맨드의 서브커맨드로 추가하고, 새 최상위 커맨드가 필요하면 먼저 확인을 요청한다.
- 커맨드·서브커맨드·옵션 이름에는 공백을 사용할 수 없다. 여러 단어로 된 동작은 서브커맨드나 옵션으로 나눈다.
- 이름은 1~32자, 설명은 1~100자 제한을 지킨다. 한 커맨드의 서브커맨드와 옵션은 각각 최대 25개다.
- 숫자 옵션에는 허용 범위(`setMinValue`, `setMaxValue`)를 지정하고, 값이 없으면 기본값을 적용한다. 현재 `집중시간`·`휴식시간`은 1~180분이다. 선택지가 고정된 옵션은 `addChoices`를, 폴더 내용처럼 바뀌는 선택지는 `setAutocomplete`를 우선 검토한다.
- 기존 커맨드·서브커맨드·옵션 이름을 바꾸거나 제거하는 것은 사용자가 쓰는 인터페이스 변경이므로 먼저 확인을 요청한다.
- 커맨드 정의를 변경하면 `도움말` 서브커맨드의 안내 문구와 `README.md`의 명령어 표를 함께 갱신한다.

## 커맨드 등록

- 커맨드는 `ready` 시점에 `rest.put(Routes.applicationCommands(...))`로 전역 등록한다. 이 방식은 배열에 없는 기존 커맨드를 덮어쓰므로 `commands` 배열이 등록할 전체 목록이 되도록 유지한다.
- 길드 단위 등록, 별도 배포 스크립트 등 등록 방식을 바꾸려면 먼저 확인을 요청한다.
- 현재 사용하는 `ready` 이벤트는 discord.js 14.25 타입에서 deprecated이며 `clientReady`(`Events.ClientReady`)로 대체된다. 전환은 별도 작업으로 진행한다.

## 인터랙션 응답

- 인터랙션에는 3초 안에 `reply` 또는 `deferReply`로 응답한다. 음성 연결, 파일 처리처럼 시간이 걸릴 수 있는 작업을 먼저 수행해야 한다면 `deferReply` 후 `editReply`를 사용한다.
- 하나의 인터랙션에 `reply`를 두 번 호출하지 않는다. 첫 응답 이후의 추가 메시지는 `followUp`, `editReply` 또는 채널 메시지로 보낸다.
- 안내·오류·조건 미충족 안내와 도움말·목록 조회 결과는 ephemeral로 응답하고, 타이머 시작·진행·중지와 배경음·알림음 설정 결과는 공개 메시지로 보낸다.
- ephemeral 지정 방식은 기존 코드와 일관되게 유지한다. 현재 코드의 `ephemeral: true`는 discord.js 14.25 타입에서 deprecated이며 `flags: MessageFlags.Ephemeral`로 대체된다. 지정 방식을 바꾸려면 코드 전체를 한 번에 바꾸는 별도 작업으로 진행한다.
- 핸들러는 처리할 인터랙션 종류와 커맨드 이름을 먼저 확인하고, 해당하지 않으면 조기 반환한다.
- 사용자 멘션은 `<@userId>`, 시각 표시는 Discord 타임스탬프(`<t:unix:R>` 등)를 사용한다.

## 중복 실행과 사용자 단위 상태

- 같은 사용자의 타이머가 이미 진행 중이면 새로 시작하지 않고 중지 방법을 안내한다. 휴식이 끝나 자동 종료를 기다리는 타이머(`ended`)는 진행 중으로 보지 않고 정리한 뒤 새로 시작한다.
- 음성 연결은 서버(길드)당 하나이므로, 같은 서버에서 다른 사용자의 타이머가 진행 중이면 시작하지 않고 안내한다.
- 사용자별 상태는 `interaction.user.id`를 키로 관리한다. 여러 사용자가 동시에 사용해도 서로의 타이머와 설정이 섞이지 않게 한다.
- 음성 채널이 필요한 기능은 실행 전에 사용자의 음성 채널 접속 여부를 확인하고, 조건을 충족하지 못하면 필요한 행동을 안내한다.

## 인텐트와 권한

- `GatewayIntentBits`는 기능에 필요한 최소한만 요청한다. 현재 `Guilds`, `GuildVoiceStates`만 사용한다.
- 새 인텐트, 특히 Discord 개발자 포털에서 별도로 활성화해야 하는 Privileged Intent를 추가하려면 먼저 확인을 요청한다.
