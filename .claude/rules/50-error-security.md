# 예외 처리, 로깅 및 보안

## 예외 처리

- 예외를 빈 `catch`로 무시하지 않는다.
- 인터랙션 처리 중 오류가 나면 사용자에게 원인과 다음 행동을 ephemeral로 안내한다. 이미 응답했거나(`interaction.replied`) 응답을 미뤘다면(`interaction.deferred`) `followUp` 또는 `editReply`를 사용한다.
- 사용자에게 스택 트레이스나 내부 오류 메시지를 그대로 보여주지 않는다.
- 예상 가능한 실패(음성 채널 미접속, 파일 없음, 이미 진행 중인 타이머, 권한 부족)는 조건 검사로 먼저 처리하고, 예상하지 못한 오류는 로그를 남긴 뒤 안내한다.
- 음성 연결, 플레이어, 클라이언트의 비동기 오류가 처리되지 않은 채 프로세스를 종료시키지 않도록 한다.
- 오류가 발생해도 해당 사용자의 타이머와 음성 연결이 남지 않도록 정리한다.
- 채널에 메시지를 보낼 수 없는 경우(권한 부족, 채널 삭제 등)에도 타이머 흐름이 중단되지 않는지 검토한다.

## 권한

- 음성 채널 접속·발화나 메시지 전송에 필요한 봇 권한이 없을 수 있음을 고려하고, 실패 시 필요한 권한을 안내한다.
- 봇 권한이나 OAuth2 초대 범위를 늘리려면 먼저 확인을 요청한다.

## 로깅

- 로그는 `console.log`, `console.error`를 사용하며 기존처럼 상태를 나타내는 이모지 접두어(✅, 🔄, ❌)를 따른다.
- 오류 로그에는 어떤 커맨드·사용자 흐름에서 발생했는지 알 수 있는 문맥을 포함한다.
- 봇 토큰, 인터랙션 객체 전체, 사용자 개인정보를 로그나 메시지에 출력하지 않는다.

## 보안 및 환경 변수

- 봇 토큰은 `.env`의 `DISCORD_TOKEN`으로만 읽고, 시작 시 값이 없으면 원인을 알리는 오류로 즉시 종료한다. 토큰을 코드, 문서, 커밋, 로그에 포함하지 않는다.
- `.env`는 커밋하지 않는다. 새 환경 변수를 추가하면 이름과 용도를 문서에 기록하고, 실제 값은 기록하지 않는다.
- `.env` 파일은 읽거나 수정하기 전에 확인을 요청한다.
- 사용자가 입력한 파일명으로 경로를 만들 때는 허용된 오디오 디렉토리 밖을 가리키지 않도록 검증한다(`..`, 경로 구분자 차단 또는 `path.basename` 사용).
- 사용자 입력을 메시지에 그대로 넣을 때는 `@everyone`, `@here`, 역할 멘션이 의도치 않게 호출되지 않도록 `allowedMentions` 적용을 검토한다.
