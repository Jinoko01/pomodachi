# 오디오 설정 영속 저장 설계

- 작성일: 2026-10-16
- 상태: 설계 승인됨, 구현 전

## 1. 배경과 목표

- 현재 사용자 오디오 설정(`userAudioSettings`, `src/audio.ts`)은 메모리에만 있어 봇을 재시작하면 초기화된다(`docs/spec.md` §5, §7).
- 목표: `/뽀모도로 배경음`, `/뽀모도로 알림음`으로 바꾼 설정이 봇을 재시작한 뒤에도 유지되게 한다.
- 규칙 문서(`rules/30-code-structure.md`)에는 "영속 저장소는 통계 기능 작업에서 함께 설계한다"고 되어 있으나, 사용자 요청에 따라 설정 저장을 먼저 진행한다. 해당 규칙 문구를 이번 작업에서 함께 갱신한다.

### 범위에 포함하지 않는 것

- 통계·랭킹 등 다른 데이터의 저장. 통계 작업에서 SQLite 등으로 옮길 때 이 파일을 이전한다.
- 진행 중인 타이머(`activeTimers`)의 복원. 재시작 시 타이머는 지금처럼 사라진다.
- 새 슬래시 커맨드·옵션, 새 패키지, 새 `src/` 파일.

## 2. 결정 사항

| 항목 | 결정 | 이유 |
|------|------|------|
| 저장소 | JSON 파일 | 새 패키지 없이 Node 20.11 요구 사항을 유지한다. 데이터가 작아 이후 이전이 쉽다. |
| 코드 위치 | `src/audio.ts` | `userAudioSettings`와 같은 곳에 두어 파일 구조와 의존 방향(`interactions → audio`)을 유지한다. |
| 쓰기 방식 | 동기, 임시 파일 후 `rename` | 설정 변경은 드물고 파일이 작다. 동시 쓰기 경합과 쓰기 중 종료로 인한 손상을 피한다. |

## 3. 저장 파일

- 경로: 프로젝트 루트의 `data/settings.json` (`ROOT_DIR` 기준, 오디오 폴더와 같은 방식).
- `data/`는 저장할 때 없으면 만든다(`saveAudioSettings` 안에서 `recursive: true`). 모듈 로드 시 폴더 생성이 실패해 봇 시작이 막히지 않도록 하기 위해서다. `data/`는 `.gitignore`에 추가한다.
- 형식:

```json
{
  "version": 1,
  "users": {
    "123456789012345678": { "bgmName": "Moonlight_ 월광_국악.mp3", "notifyName": "기본알림음.mp3" },
    "234567890123456789": { "bgmName": null, "notifyName": "자명종소리.mp3" }
  }
}
```

- `version`은 이후 형식 변경·저장소 이전 시 구분용이다. 현재는 `1`만 허용한다.

## 4. 동작

### 4.1 불러오기 (`audio.ts` 로드 시 1회)

1. `data/settings.json`이 없으면 빈 Map으로 시작한다.
2. 파일을 읽어 JSON으로 파싱한다. 파싱에 실패하거나 최상위 구조(`version === 1`, `users`가 객체)가 맞지 않으면:
   - 원본을 `data/settings.json.broken`으로 이름을 바꾼다(기존 `.broken`은 덮어쓴다).
   - `❌ 설정 파일을 읽을 수 없어 빈 설정으로 시작합니다` 로그를 남기고 빈 Map으로 시작한다.
   - 이름을 바꾸는 이유: 다음 저장 때 손상된 원본을 덮어써 복구 기회를 잃지 않기 위해서다.
3. `users`의 각 항목은 `bgmName`이 `string | null`, `notifyName`이 `string`일 때만 Map에 넣는다. 그렇지 않은 항목은 건너뛰고 사용자 ID를 포함한 `⚠️` 로그를 남긴다.
4. 파일명이 실제 오디오 폴더에 있는지는 불러올 때 검사하지 않는다. 지금처럼 타이머 시작·알림음 재생 시점에 검사한다(`docs/spec.md` §3.3, §3.4).
5. 파일 읽기 자체가 예외(권한 등)로 실패하면 `❌` 로그를 남기고 빈 Map으로 시작한다. 봇 시작은 막지 않는다.

### 4.2 저장 (`saveAudioSettings(): boolean`)

- `userAudioSettings` 전체를 3절의 형식으로 직렬화해 `data/settings.json.tmp`에 쓴 뒤 `data/settings.json`으로 `rename`한다.
- 성공하면 `true`, 예외가 나면 `❌` 로그(어떤 흐름에서 실패했는지 포함, 토큰·인터랙션 객체 제외)를 남기고 `false`를 반환한다. 예외를 다시 던지지 않는다.

### 4.3 호출 지점 (`interactions.ts`)

- `handleBgm`, `handleNotify`에서 `userAudioSettings.set(...)` 직후 `saveAudioSettings()`를 호출한다.
- 저장 결과와 관계없이 메모리 설정은 적용된 상태로 유지한다(이번 실행 동안은 정상 동작).
- 저장에 실패하면 기존 공개 응답 끝에 줄을 바꿔 다음 문구를 붙인다.

```text
⚠️ 설정을 파일에 저장하지 못해 봇을 재시작하면 초기화됩니다.
```

- 그 외 응답 문구, 공개 여부, `allowedMentions`는 바꾸지 않는다.

## 5. 변경 파일

| 파일 | 변경 |
|------|------|
| `src/audio.ts` | `data/` 경로 상수, 불러오기 로직, `saveAudioSettings` 추가 |
| `src/interactions.ts` | `handleBgm`·`handleNotify`에서 저장 호출과 실패 문구 |
| `.gitignore` | `data/` 추가 |
| `README.md` | "설정은 봇이 재시작되면 초기화됩니다" 문구를 저장 위치 안내로 교체, 프로젝트 구조에 `data/` 추가 |
| `docs/spec.md` | §5 상태 관리, §7 "설정 비영속" 항목 갱신 |
| `.agents/rules/30-code-structure.md`, `.claude/rules/30-code-structure.md` | 상태 관리 절의 영속 저장소 문구 갱신(두 파일 동일하게) |

- `/뽀모도로 도움말` 응답에는 초기화 관련 문구가 없으므로 바꾸지 않는다.

## 6. 검증

- `pnpm typecheck`, `pnpm build`를 실행한다.
- 다음 시나리오는 봇을 실행해야 확인할 수 있다. 봇 실행은 사용자 승인 후에만 하며, 실행하지 못하면 미확인으로 보고한다.
  1. 배경음·알림음 설정 → 봇 재시작 → `/뽀모도로 시작` 시 설정이 유지되는지
  2. `data/` 폴더가 없는 상태로 시작했을 때 폴더가 만들어지고 설정이 저장되는지
  3. `settings.json`을 일부러 깨뜨린 뒤 시작했을 때 `.broken`으로 옮겨지고 봇이 정상 시작하는지
  4. 저장 실패(예: `data/settings.json`을 읽기 전용으로 설정) 시 경고 문구가 붙는지
